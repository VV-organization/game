# Подключение Clickit

> Исполнение: superpowers:executing-plans; проверка изменений отдельным ревьюером.

**Цель:** включить реальное пополнение Fapix через выданный магазин Clickit 1502, сохранив существующий кошелёк и UI.
**Основание:** пользователь поручил подключить платежи, предоставил собственные credentials и разрешил исследовать соседние проекты/серверы. Дополнительное согласование реализации не требуется.
**Архитектура:** существующий `arco` adapter уже реализует Clickit API. Сохраняем внутреннее имя режима/настройки для совместимости; меняем актуальный hosted origin на payment.clickit.team. Проверяем доступные методы магазина перед публичным включением. Подтверждение оплаты — только серверный status с проверкой shop/order/amount/currency/method. Callback подписан RSA-SHA1, начисление транзакционно и идемпотентно.
**Стек:** React/TypeScript, Node 24, SQLite, Caddy, Docker Compose, GitHub Actions.

## Ограничения

- Секреты только `/home/game-runner/.envs/game/.env` (600), не в git/клиенте/логах. Credentials соседей не копировать.
- Суммы 1–100000 целых RUB, 1 RUB = 2 Fapix. Реального списания без участия пользователя не выполнять.
- Существующие аккаунты и платежные записи сохранять; тестовые provider invoices не удалять.
- Реальные запросы создания и открытие формы доказывают доступность, но не settlement.
- CSP разрешает POST только self и payment.clickit.team; общие wildcard не добавлять.

## Фокус ревью

- Настоящий банковский callback и повторный status не должны удваивать баланс; возврат из браузера не подтверждает оплату.
- Несовпадение merchant/shop/method/amount должно блокировать credit.
- После неопределённого ответа создания повтор не создаёт второй платёж.
- CSP и POST-переход должны пропускать реальную форму и возвращать на fapixracing.com.
- Настройки провайдера не должны утечь в браузер или репозиторий; недоступный метод нельзя показывать рабочим.

## Решения и проверка

- СБП отключён по факту ответа НСПК HTTP400/RQ05014; production ARCO_PAY_METHODS=card. Повторное включение требует рабочего маршрута провайдера.
- Независимое ревью: критического обхода settlement нет. Найден P2 очереди — исправлен через last_checked_at; тест 51 операции RED (balance0) → GREEN (balance20, одна проводка).
- Добавлен составной тест настоящего adapter и HTTP callback с тестовой RSA-подписью, повторным callback/polling/reconcile и единственной проводкой. Реальный банк этот тест не затрагивает.
- Проверки: npm test — 373/373; npm run build и format:check — PASS.

- Публичная проверка: POST формы Clickit200, восстановление исходного счёта, mobile history, callback401, SBP503, balance0/ledger0; подробные ID и ссылки CI в docs/research/payment-integration.md.
