# FApix Racing Implementation Plan

> For agentic workers: use superpowers:subagent-driven-development. Independent path ownership; root integrates and reviews.

**Goal:** Working browser kart racing with VV-136 economy and catalog.
**Architecture:** React UI, isolated Three.js simulation, Node API and SQLite ledger, Arco provider adapter.
**Tech Stack:** TypeScript, React, Vite, Three.js, Express, SQLite, Vitest.
**Spec:** ../specs/2026-11-06-fapix-design.md

## Global Constraints

- Exactly 1 RUB = 2 Fapix; integer monetary accounting.
- At least 300 products, required category minima, six explicit quick amounts.
- Original reference assets and typography. All purchases server-authoritative and nonrepeatable.
- No provider secrets in browser, no client-declared payment success, no pretending sandbox money is real.

## Review Focus

- Duplicate requests/callbacks never credit or purchase twice.
- Invalid amounts, absent account, insufficient balance, provider timeout have explicit states.
- Track laps require ordered progress; pause freezes race, restart resets it.
- Mobile and keyboard controls must work; no clipped dialogs or inaccessible inputs.
- Every equipped item influences corresponding rendered appearance; owned state survives reload.
