# План выпуска регистрации с подтверждением почты

Все игроки начинают с новой регистрации. Единственный способ получить игровой аккаунт — подтвердить адрес кодом из письма. Дальше игрок входит по логину и паролю. Основа реализации — Express, SQLite, Nodemailer и существующий клиент React. [Согласованная спецификация](../specs/2026-11-24-registration-email-code-design.md).

### 1. Незавершённая регистрация и подтверждение в SQLite

- [ ] В `server/store.test.ts` воспроизвести два одновременных подтверждения, истечение 10 минут, блокировку после пяти ошибок, конфликт логина или почты и повтор после перезапуска. Начать с тестов на временной базе.
- [ ] В `server/store.ts` добавить хранение незавершённых регистраций отдельно от пользователей, версий отправки, времени принятия SMTP и расхода лимитов. В новой схеме сделать подтверждённые почту и дату обязательными для каждого пользователя. Уникальность обеспечить по нормализованной почте и существующему правилу для логина.
- [ ] Добавить атомарное погашение кода с созданием пользователя и сессии. Переиспользовать SQL создания аккаунта внутри одной транзакции. Нынешний `Store.register` сам вызывает `BEGIN IMMEDIATE`, поэтому вложенный вызов потребует выделения общей операции вставки.
- [ ] Проверить, что сбой перед выдачей ответа допускает обычный вход с выбранным паролем, а неуспешное подтверждение оставляет базу без частично созданного пользователя. Запустить `npx vitest run server/store.test.ts`.

### 2. Письмо Purelymail и HTTP API

- [ ] В `server/app.test.ts` проверить полный цикл с подменой отправителя и часов. Включить ведущий ноль в коде, двойное нажатие, смену адреса, просроченный ответ SMTP, отказ при повторной отправке и вход при выключенной почте.
- [ ] Добавить `server/registration-mail.ts` с функцией `sendRegistrationCode(to: string, code: string): Promise<void>`. Настроить Nodemailer, TLS, ограниченное время подключения и ответа, отправителя и текст из спецификации. В `package.json`, lock-файле и `.env.example` описать зависимости и имена настроек. Боевые значения задаются в окружении сервера.
- [ ] Реализовать в `server/app.ts` начало, восстановление, повтор и подтверждение регистрации по контракту спецификации. Привязать запросы к cookie регистрации. Для конкурентных первых запросов использовать один ключ операции формы. До SMTP зарезервировать версию отправки, после успешного ответа активировать именно её. При отказе сохранить предыдущий активный код.
- [ ] Добавить лимиты отправок и проверку HMAC с отдельным серверным ключом. Для лимита по IP проверить фактическую цепочку Caddy → Express. Произвольный заголовок клиента не должен менять адрес для подсчёта. Проверить 60 секунд между письмами, 5 отправок на адрес и 20 на IP в час.
- [ ] Обновить регистрацию пользователей в тестах платежей и приложения. Запустить `npx vitest run server`; проверить, что гостевое пополнение существующего логина по-прежнему работает.

### 3. Регистрация в интерфейсе и допуск к гонке

- [ ] Обновить `src/components/Auth.tsx`, `src/shared/types.ts` и `src/lib/api.ts` по контракту API. В форме регистрации реализовать ввод кода, восстановление после перезагрузки, отсчёт до повтора и исправление адреса. Обычная форма входа содержит логин и пароль.
- [ ] В `src/App.tsx` направить гостя в регистрацию со старта тренировки, онлайн-подбора, приглашения и восстановления соединения. После подтверждения продолжить выбранное действие. В `server/app.ts` разрешать игровое WebSocket-подключение только по сессии подтверждённого пользователя.
- [ ] Обновить тесты в `server/online.test.ts` и добавить проверки формы и входа в игру. Проверить анонимное открытие `/play`, ссылку на комнату, повторный вход с выключенным SMTP и отклонение гостевого WebSocket. Запустить `npm test`, `npm run format:check` и `npm run build`.

### 4. Однократный сброс при выпуске

- [ ] На отдельной тестовой базе отрепетировать переключение через `DATABASE_PATH`. Повторный запуск контейнера должен сохранять уже созданные новые аккаунты. Сброс выполняется операцией выпуска, а не кодом при старте приложения.
- [ ] При выпуске переключить сервис на пустую рабочую базу. Проверить, что список аккаунтов пуст и старая сессия больше не открывает игру.
- [ ] Пройти регистрацию на тестовом ящике, ввести код из полученного письма, затем выйти и войти по логину и паролю. Проверить тренировку, онлайн-вход и сохранность нового аккаунта после перезапуска.
