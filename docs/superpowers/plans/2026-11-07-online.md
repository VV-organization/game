# Online Racing Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development. Execute continuously within assigned file ownership; root integrates and commits.

**Goal:** Real shared browser races with bounded matchmaking, honest AI fill, authoritative results and recovery.

**Architecture:** Reuse pure simulation on the HTTP server; `ws` transport; stable slot IDs and native browser client; adapt existing Three.js renderer.

**Tech Stack:** React/Three.js/TypeScript, Node24, Express, SQLite, ws, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-07-online-design.md`

## Global Constraints

- Six seats, waiting deadline30s, reconnect12s, physics60Hz, snapshots20Hz; no fake humans or payment changes.
- Server derives equipped customization from session/catalog. No trusting client transforms/results.
- Existing local formats/controls/tests remain functional. Stable numerical car IDs.
- No public deployment claims until external browser connectivity is verified.

## Review Focus

- Human slot1 must drive independently from slot0; hidden/paused client must not pause server.
- Queue boundaries and cancel/rejoin never duplicate seats or reset deadline.
- Resume identity/token, expired inputs, malformed controls and pressure limits.
- Finish/elimination/DNF consistent across clients; no race ending when only slot0 finishes.
- Renderer cleanup, responsive lobby, local record provenance and no production secrets in snapshots.

### Task 1: Multiplayer physics

Owner: simulation implementer. Files `src/game/simulation.ts`, `simulation.test.ts` only.

Interfaces: RaceDriver `{id,kind,name,customization}`; RaceOptions `{drivers?,completion?:'local'|'all'}`; optional fourth createRace argument. Car adds driverKind,customization,lastPower,didNotFinish. RaceState adds completion,pulses. Export stepRaceDrivers, resetCar, useCarPower, getCarPosition; existing wrappers remain. getRaceResult accepts optional carId. Shared result allows didNotFinish.
