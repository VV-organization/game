# Эксплуатация онлайн-гонок

Документ описывает текущий код `server/index.ts`, `server/online.ts`, `server/app.ts`, `vite.config.ts` и npm scripts. Это инструкция, а не свидетельство публичного развёртывания. Публичный deployment target и remote для выпуска не предоставлены.

## Локальный запуск с существующей базой

Нужен Node.js 24. API использует `node:sqlite`; установленный `sqlite3` нужен только для приведённого ниже безопасного снимка существующей базы. Не открывайте единственную старую базу непосредственно для экспериментов: приложение создаёт таблицы, сессии и другие записи при работе.

Если старый процесс ещё работает, сделайте согласованный backup через SQLite; не копируйте отдельно основной файл базы в WAL-режиме. Укажите собственный путь вместо placeholder, не выводите содержимое базы или `.env`:

```sh
online_workdir=$(mktemp -d "${TMPDIR:-/tmp}/fapix-online.XXXXXX")
chmod 700 "$online_workdir"
sqlite3 '/absolute/path/to/legacy/fapix.sqlite' ".backup '$online_workdir/fapix.sqlite'"
npm ci
DATABASE_PATH="$online_workdir/fapix.sqlite" PAYMENT_MODE=disabled HOST=127.0.0.1 PORT=3001 NODE_ENV=development npm run dev
```

Команды создают новый закрытый временный каталог вне репозитория; база содержит данные аккаунтов и не должна попадать в git. Временное хранилище не подходит для production: система может его очистить. Исходная legacy-база остаётся неизменной; рабочая копия изменяется при использовании приложения. Старую метку экономики `sandbox` разрешено читать в `disabled`, без симулятора и начислений. В режиме `arco` такая база отклоняется; перенос тестовых балансов в настоящую экономику не поддерживается.

Для новой пустой базы пропустите backup и используйте новый `DATABASE_PATH`. Без переменной путь по умолчанию — `data/fapix.sqlite`. Приложение автоматически читает корневой `.env`; заданные переменные процесса имеют приоритет. Не перезаписывайте существующий `.env` ради теста.

Откройте `http://127.0.0.1:5173`. Vite слушает строго 5173 и проксирует `/api` и `/ws` на `127.0.0.1:3001`; изменение `PORT` само по себе не перенастраивает proxy. Для локальной проверки не задавайте публичный `PUBLIC_URL`: если он уже сохранён в `.env`, используйте `PUBLIC_URL=http://127.0.0.1:5173` в команде запуска. Иначе origin браузера будет отклонён. Development без `PUBLIC_URL` допускает `http://127.0.0.1:5173`, `http://localhost:5173` и настроенный прямой HTTP-адрес API.

Проверьте две независимые браузерные сессии: обычное и приватное окно. Две вкладки одной сессии — один actor и не занимают два места. В обоих окнах выберите одинаковые трассу и формат. Проверьте общий состав, одинаковый старт, движение второго участника, AI-метки и согласованный итог. `GET /api/health` подтверждает доступность HTTP, но не прохождение этого сценария.

## Production: один процесс и один origin

Поддерживаемые настройки перечислены в `.env.example`: `HOST`, `PORT`, `DATABASE_PATH`, `PUBLIC_URL`, `PAYMENT_MODE`, а для реальных платежей — `ARCO_PAY_*`. Отдельных переменных адреса WebSocket, лимита подбора, reconnect, Redis или масштабирования нет. Подбор 30 секунд и восстановление 12 секунд заданы в `src/shared/online-protocol.ts`.

Пример собственных значений окружения для HTTPS-развёртывания без платежей:

```dotenv
HOST=127.0.0.1
PORT=3001
DATABASE_PATH=/var/lib/fapix-racing/fapix.sqlite
PUBLIC_URL=https://racing.example
PAYMENT_MODE=disabled
```

`racing.example` — placeholder, а не существующий deployment. Выделите постоянный каталог базы с доступом только сервисному пользователю. Для контейнера допустим `HOST=0.0.0.0` за reverse proxy и постоянный volume. Не публикуйте SQLite, `.env` и резервные копии через web-root.

```sh
npm ci --include=dev
npm run build
npm start
```

`npm start` устанавливает `NODE_ENV=production`; `tsx` находится в devDependencies, поэтому установка с `--omit=dev` не подходит. API и `dist/` раздаются одним HTTP-сервером. TLS завершает reverse proxy. Браузер сам выбирает `wss://<текущий-host>/ws/race` для HTTPS; cross-origin WebSocket не предусмотрен.

Reverse proxy должен передавать `/`, `/api/*` и точный `/ws/race` в один процесс, сохранять Cookie и Origin и поддерживать HTTP/1.1 Upgrade. Например, внутри собственного HTTPS `server` блока nginx:

```nginx
location /ws/race {
    proxy_pass http://127.0.0.1:3001;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header Origin $http_origin;
    proxy_read_timeout 60s;
}
location / {
    proxy_pass http://127.0.0.1:3001;
    proxy_set_header Host $host;
}
```

Настройка сертификата/домена относится к выбранному окружению. `PUBLIC_URL` должен совпадать с внешним HTTPS-origin без пути. WebSocket upgrade проверяет разрешённый origin и идентичность по cookie: чужой origin получает 403, отсутствие допустимой сессии — 401. Production-cookie имеет Secure, поэтому обычный HTTP на внешнем домене не подходит. Клиент сначала получает `/api/session`, затем открывает WebSocket.

Платежи остаются `disabled`; онлайн не требует мерчанта и не начисляет Fapix. Реальный платёжный режим требует отдельной настройки и проверки из README. Не копируйте секреты другого проекта в этот deployment.

## Ограничения и поведение при сбое

- Один Node.js-процесс, одна SQLite-база на постоянном диске. Комнаты, авторитетная симуляция и reconnect-токены находятся в памяти; Redis, общий room-store и межпроцессная маршрутизация отсутствуют. Sticky sessions сами по себе не дают корректного масштабирования.
- Перезапуск/падение процесса теряет активные комнаты; reconnect не переживает restart. Завершённые результаты отображаются по серверному состоянию, история браузера локальная; отдельного долговечного серверного журнала результатов гонок нет.
- Сервер ограничивает число комнат до 64 и подключений до 256; это защитные лимиты, а не измеренная производительность. Нагрузочный предел конкретного хоста не подтверждён.
- Комната вмещает 6 участников; на дедлайне добавляются AI. Идущая/полная комната новых игроков не принимает. Приглашение и ручной код применяют настройки комнаты, независимо от текущего выбора игрока. Повтор запускает новый подбор, без сохранения группы.
- Временный обрыв сбрасывает управление человека, не подменяет его скрытым AI; 12 секунд на возврат в исходный слот, затем DNF. Явный выход прекращает право на восстановление. После первого финиша — 30 секунд до окончания, общий предел 5 минут; завершённая комната удаляется через 30 секунд.
- Отдельных ranked-рейтингов, чата, наблюдения, наград за гонки и независимого multiplayer-сервиса нет. Отдельная публичная система мониторинга/деплоя не настроена этой реализацией.

## Остановка

В development используйте Ctrl+C в терминале `npm run dev`; `concurrently -k` завершает связку процессов. Для production отправьте SIGTERM конкретному PID приложения через его process manager, а не всем процессам Node на машине. Обработчик SIGINT/SIGTERM останавливает фоновую сверку, сетевой таймер и WebSocket-соединения, закрывает HTTP-сервер, затем SQLite. Активные гонки не доигрываются при остановке. Перед обновлением учитывайте потерю комнат; автоматического drain-режима нет.

После остановки резервную копию также делайте SQLite backup-операцией. Не удаляйте базу, WAL/SHM или исходную legacy-копию для устранения ошибки запуска.
